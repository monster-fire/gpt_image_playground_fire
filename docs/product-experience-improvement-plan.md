# 产品体验优化执行文档

日期：2026-09-15。状态：P0 五项已完成并通过本地验证；P1/P2 仍为待实施建议。逐项验证结果见第 6 节。

## 1. 评估范围与产品目标

目标用户是将应用部署在 NAS、经常进行多轮图片生成、比较结果、挑选收藏的个人用户。优化目标按顺序为：减少误操作和重复生成；让等待、失败和保存状态可判断；降低多轮多图操作成本；保证手机上可完成相同核心任务。

依据为当前工作区源码，包含已完成的 Agent 上下文压缩与 IndexedDB 缓存改动，不只依据 Git 提交版本。阅读范围覆盖 App、输入栏、Agent、任务卡片、详情与灯箱、历史、设置、收藏、请求适配、持久化，以及 Docker/Nginx/运行时配置注入。

实际浏览器检查了 1440×900 和 390×844 下的空画廊、API 设置和进入 Agent 时的配置阻断弹窗，所查页面没有横向页面溢出。使用独立浏览器数据，不读取用户真实配置，不发起模型调用。长对话、生成中、数据异常等结论以源码为依据，尚未完成这些场景的完整交互实测。截图留在本地 `.omx/diagnostics/ux/`，不作为文档依赖或提交附件。

### 服务端现状

- 已新增 `server/app.mjs` 最小 NAS 服务，负责登录、会话、配置文件读写和受保护代理；生产镜像运行 Node 与 Nginx，私有配置不再注入静态 JS。
- `scripts/mock-image-api.mjs` 是测试服务，不是生产后端。外部供应商后端源码不在仓库，不能据本仓库推断其内部实现。
- NAS 登录与配置接口随 UX-17 实施；收藏上传仍按 [NAS 执行文档](nas-auth-execution-plan.md) 待实施。

### 保持的约束

| 数据或操作 | 产品约定 |
| --- | --- |
| 普通原图、画廊、对话、Agent 压缩缓存 | 浏览器本地。 |
| 收藏原图、对应提示词、收藏夹 | NAS 方案实施后以 NAS 为准。 |
| API 配置 | Docker NAS 模式通过接口读写 `config/gpt-image-playground.json`；浏览器仅保留内存工作副本。 |

| 视觉方向 | 延续现有布局和中文界面，优先改善信息、动作和状态；不将工作界面改为展示型首页。 |

## 3. 具体修改项

### UX-01：重试前明确配置和范围

**现状与问题**：已有重试、复用配置、临时复用历史 API 配置。`src/store.ts:3824` 的 `retryTask` 直接取当前 activeProfile；`reuseConfig` 则可匹配原任务配置。用户切换供应商后点“重试”，可能在不知情时更换模型、参数或计费渠道。批量部分失败时，重试也需要明确是否会重复成功结果。

**修改**：失败任务默认按原任务 profile ID 解析当前有效配置，不保存或复活历史密钥；原配置不存在时进入配置选择。把“按原配置重试”和“使用当前配置生成”作为有区别的动作；默认动作在菜单或确认区展示实际模型。多图任务先明确失败输出和整批重做的边界，再决定是否提供“仅重试失败项”。不自动重复已成功生成的图片。

**验收**：原配置 A、当前配置 B 时，普通重试使用有效 A；A 被删时不静默使用 B；部分成功任务保留成功结果；用户知道本次会新建请求。原任务的提示词、参考图、遮罩、参数与当前接口兼容性都经过校验。

**实施状态（2026-09-15）**：已完成。重试会优先按原任务 `apiProfileId` 解析当前有效配置；原配置缺失时弹出确认，不直接请求当前配置。部分失败任务会新建仅包含失败数量的新任务，原任务成功结果保留。NAS 模式下生成/重试前等待配置保存队列，配置保存失败会阻止新请求。

**验证**：`npm.cmd test -- src/lib/taskRecovery.test.ts src/store.test.ts` 通过；`npm.cmd run build` 通过；`npm.cmd test` 通过。

### UX-02：失败可判断、可处理

**现状与问题**：详情页已有完整错误复制；API 层已有跨域、透明背景与部分流式兼容提示。`src/lib/imageApiShared.ts:182` 的 `getApiErrorMessage` 返回字符串，JSON message 可能覆盖 HTTP 状态，非 JSON 则直接返回正文。此前 502 和 456 场景说明用户难以区分本地准备、上传、上游、下载和本地保存失败。

**修改**：保留现有错误查看能力，新增结构化错误信息：阶段、HTTP 状态、错误类型、请求 ID、耗时、请求字节数和经过截断脱敏的技术详情。主视图显示一句可执行结论和相应动作，例如检查配置、重新下载结果、调整上下文或手动重试。HTML 防护响应按纯文本归类，不渲染脚本。502 不统一写成超时，网络失败也不直接认定为跨域。

**服务端配合**：在正确的 Nginx `http` 配置作用域定义日志格式，记录 `$request_length`、`$request_time`、`$upstream_status`、`$upstream_response_time` 和关联 ID；不能把整个 `log_format` 直接塞进现有 server 模板。代理透传/返回必要 ID；跨域直连时仅读取供应商允许暴露的头。日志不记录认证头、Cookie、提示词、图片正文。

**验收**：401、429、502、客户端主动停止、请求超时、HTML 防护、结果下载失败、IndexedDB 保存失败各有不同状态；复制诊断不含密钥与图片数据。只有客户端计时器触发等明确证据才能显示“超时”。不自动重试可能已经受理的付费生成。

**实施状态（2026-09-15）**：已完成。错误对象保留阶段、HTTP 状态、错误类型、耗时、请求体大小和脱敏详情；HTML 防护响应按文本截断展示，不执行脚本。代理和前端错误边界区分 NAS 会话、供应商鉴权、网络失败、上游失败、下载失败和本地保存失败。502 主文案不再直接写成超时；接近超时时只提示检查代理日志、上游响应和超时配置。

**验证**：

### UX-04：统一恢复中、停止和失败

**现状与问题**：`TaskCard.tsx:298` 和 `DetailModal.tsx:265` 同时定义 fal/custom 重连状态，但卡片 `:445/:465/:641` 与详情部分展示分支只判定 fal。自定义任务可能一边查询恢复、一边呈现失败和重试动作。

**修改**：对当前仍允许查询的流程统一推导展示状态，区分等待恢复、明确失败、用户停止。与 NAS 计划中“刷新关闭不自动续跑”一起审查，停用恢复的部署不再创建自动查询状态。停止动作不许诺外部服务已停止计费。

**验收**：有远端 ID 且正在查询时不显示普通新生成重试；已停止不自动恢复；页面刷新后的行为符合已确认的部署约定。该项不能借体验优化重新引入后台任务系统。

**实施状态（2026-09-15）**：已完成。卡片与详情页共用恢复中判断，fal/custom 恢复中都显示查询状态并隐藏普通重试；恢复中任务在 store 层也会阻止重复重试。NAS 模式首次初始化不再调度 fal/custom 自动恢复，会把遗留 running/recoverable 标记为中断。新增 `stopAllActiveRequests()` 供退出登录时停止画廊请求、Agent 请求、恢复定时器和 watchdog。

**验证**：`npm.cmd test -- src/lib/taskRecovery.test.ts src/store.test.ts` 通过；`npm.cmd run build` 通过；`npm.cmd test` 通过。

### UX-05：展示准备图片进度

**现状与问题**：已完成 IndexedDB 持久压缩、增量处理和大小保护，不能再作为待开发功能重复实施。`executeAgentRound` 在调用接口前准备上下文，`AgentWorkspace` 的等待文案主要是“正在生成回复”，用户无法判断首次使用是在本地处理还是已经请求模型。

**修改**：增加准备图片、等待响应、接收回复、生成图片、保存结果等实际可观测阶段。准备阶段用数量进度，缓存命中直接跳过，快速完成时不闪烁。发送后立即锁定重复提交，准备期间也可停止。请求字节数和命中数量放诊断详情，不把编码和数据库术语堆在主界面。

**验收**：首次处理 14 张与第二次全部命中显示正确；新增 2 张只处理新增图；准备时取消不会发送模型请求，也不回写已删除图片；不得把未知供应商进度伪装成百分比。分别记录冷缓存和热缓存耗时，不预设性能提升数字。

### UX-06：降低首次使用与手机输入成本

**现状与问题**：真实空页面发送按钮禁用，原因主要在 aria-label/提示中；进入 Agent 已有“需要 Responses API 配置”和去设置入口，不能误报为没有配置校验。手机 390×844 输入区同时显示尺寸、质量、格式、透明背景、审核、数量，占用约下方 330 像素。参数仍有 `auto`、`false` 等技术值，设置中较多 URL 参数说明挤占主内容。

**修改**：未配置时在主操作位直接给“配置 API”，进入对应配置表单；不要只禁用按钮。手机默认保留提示词、参考图和发送，尺寸/数量作为常用项，高级参数按需展开并显示已修改数量。布尔值用开关，显示“自动”“关闭”等中文，底层值与导出格式不变。接口兼容细节移到高级区或帮助入口。

**验收**：不依赖悬停就能从空页面完成配置；390×844 和 360×740 下输入、添加参考图、发送、停止都可操作；软键盘弹出后发送键不被遮住。高级参数折叠不改变已有值，模式切换不丢失草稿。桌面端保留高效操作，不强制套用手机折叠规则。

### UX-07：让空间占用和缓存清理可见

**现状与问题**：设置数据页已有导出、导入和清空，但没有原图/缩略图/Agent 副本的占用分类和单独清缓存入口。用户已明确关注缓存残留。新数据库层已保证原图和副本联动删除，应继续复用该规则。

**修改**：数据页展示本地记录数量、原图与派生缓存逻辑大小、站点空间估算和最近检查时间。提供“仅清理可重建缓存”与“删除本地数据”两个明确动作。统计使用游标或可维护元信息，避免一次读入所有原图；逻辑字节与浏览器实际配额分别标注。清缓存与正在压缩的写入协调，清理完成后不被此前排队写入立即填回。

**验收**：仅清缓存后原图、任务、收藏关联和对话仍在；下一次发送按需重建。原图删除后缩略图及上下文副本都不可读；共享原图仅在无引用时删除。磁盘空间显示允许浏览器异步回收，不伪造“立即释放精确物理字节”。缓存空间不足提示可恢复状态，避免每张图重复弹提示。

### UX-08：删除前说明影响，删除后等到结果

**现状与问题**：已有对话关联任务删除、收藏夹删除选项和引用检查，不能简化为所有删除都相同。设置清空确认仍是笼统“清空所选的数据”，`ConfirmDialog` 有 awaitAction 能力但普通调用可以触发异步操作后立即关闭。

**修改**：确认区显示删除对象与数量、保留项和作用位置，异步操作统一等待提交并禁用重复触发；失败保留上下文并提供重试。区分删除对话、删除关联任务、移出收藏夹和永久删除图片。NAS 上线后进一步区分本地与 NAS；移出收藏不必另加多层确认，永久清空才使用强确认。撤销只能用于实际可恢复的归属/界面操作，不把已物理删除的数据假装可撤销。

**验收**：删除过程中不能双击重复提交，失败不显示成功；对话保留图片与连图删除各符合选项；多引用图不误删；确认信息与最终事务对象一致；删除原图仍联动上下文缓存。

### UX-09：长对话展示用缩略图，多图可连续查看

**现状与问题**：`AgentWorkspace.tsx:18` 的 64×64 `ChatImageThumb` 使用 `ensureImageCached` 读取完整原图；消息通过 activeMessages.map 展示。发送压缩不会解决显示时的解码开销。`:56` 打开灯箱时传 `[imageId]`，而灯箱已有列表导航，导致同轮参考图需要来回关闭打开。

**修改**：普通聊天小图使用现有 thumbnail cache；遮罩预览采用独立可重建预览或按可见区域生成，避免把遮罩合成与普通原图加载混用。灯箱接收本轮完整图片列表和当前索引。先做可视区加载和保留滚动位置，再依据测量决定消息分页或窗口化，不立刻引入新依赖。

**验收**：100 轮、多图片对话首屏不读取所有历史原图；滚动定位稳定，流式回复不抢走正在阅读历史的视口；同轮图片可左右键/滑动连续看，删除缺图后索引仍正确。缩略图不进入实际图片编辑请求。

### UX-10：配置编辑、保存与验证分开

**现状与问题**：`SettingsModal.tsx:412` 的 commitSettings 直接规范化并 setSettings；字段存在即时更新、失焦提交等不同方式。现在是本地保存，迁移 NAS 后不能把每次按键都当远端提交，也不能关闭弹窗后假定保存成功。

**修改**：API 配置使用草稿和明确保存动作，普通界面偏好继续即时生效。字段错误就地显示；保存失败保留草稿；保存中、已保存、版本冲突有明确状态。新增“检查配置”，分开表达格式有效、连接可达、鉴权通过、模型实际可用；不把 `/models` 成功当生图一定可用。付费模型测试必须是单独的显式动作。

**验收**：编辑错误 URL 不破坏当前运行配置；正在生成的请求使用提交快照。NAS 409 提供重新读取与保留草稿，401 保留不含密钥的编辑上下文后登录，断线不显示保存成功；未配置/已删除配置不能被本地旧副本自动补回。

### UX-11：导入导出有范围、进度与结果

### UX-17：网页与 NAS 统一鉴权，登录有效期 7 天

**现状与目标**：当前没有应用登录，页面和已启用的代理缺少会话保护。用户明确要求 Docker 启动环境变量设置密码，登录后浏览器保留 7 天有效状态。该项优先于体验微调，独立于 NAS 收藏改造交付。

**修改**：服务端读取必填 `APP_PASSWORD`；登录成功发放随机会话令牌，使用 HttpOnly Cookie 保存，固定 168 小时到期，不自动续期。浏览器不保存登录密码。刷新、关闭重开在有效期内免登，到期重新输入；退出撤销当前会话，修改密码使所有旧会话失效。会话元数据在 NAS 数据卷持久化，容器重启不重置到期时间。详细接口、Cookie、HTTPS 和生命周期规则以 [NAS 执行文档第 6 节](nas-auth-execution-plan.md#6-服务端登录与部署) 为准。

**两套凭据的职责**：应用登录会话与供应商 API Key 是两回事。应用会话只决定网页是否可以访问 NAS 的受保护服务；API Key 只用于供应商按其规则验证模型调用。不得用供应商 API Key 代替 NAS 登录，不得将应用 session 填入供应商 Authorization 头。这里“使用 API Key 的地方不需要鉴权”指不额外加入本应用会话鉴权，供应商原有的 API Key 验证仍然存在。

| 请求路径 | 应用登录会话 | 供应商 API Key |
| --- | --- | --- |
| 网页进入工作区、读取 NAS API 配置/密钥 | NAS 校验会话，登录后才开放 | 读取密钥本身仍是 NAS 私有数据操作，不用该 Key 证明已登录。 |
| 网页读写 NAS 收藏、收藏夹、媒体、下载、操作状态 | NAS 统一校验会话 | 不参与。 |
| 网页直接调用供应商生成/编辑/模型等接口 | 供应商请求不附加应用会话校验、Cookie 或 CSRF token | 沿用供应商所需的 Authorization/API Key 格式。 |
| 网页请求 NAS 的 `/api-proxy/*` | 这一跳属于网页与 NAS 交互，必须校验会话；即使请求已有 API Key 也不豁免 | 请求中供应商 Key 只供后续转发，不能当作应用会话。 |
| NAS 代理转发到供应商 | 不要求供应商识别应用会话，移除本地 Cookie/CSRF 信息 | 保留供应商所需凭据，不被会话鉴权覆盖。 |
| 浏览器内部读取 IndexedDB、压缩、预览、生成本地下载 | 不为每次本地操作新增 NAS 鉴权请求；工作区仍受页面登录状态控制 | 不参与。 |

**统一入口与客户端分工**：新增同源 NAS API 客户端处理会话 Cookie、写操作 CSRF 和会话失效；现有供应商 API 客户端保持其 Key/SDK 认证，不套用 NAS 登录拦截器。会话检查、登录和必要静态资源属于认证启动入口，不能要求先登录才能登录。NAS 业务接口与 Nginx 代理共用同一会话验证服务；验证发生在请求头阶段，鉴权子请求不重复转发大图片正文。

**401 必须区分来源**：NAS 会话过期返回明确的应用错误标记（例如 `APP_SESSION_EXPIRED`），客户端据此锁定工作区。供应商返回 401 表示供应商认证失败，应提示检查 API Key，不能退出应用登录；经 NAS 代理返回的上游 401 也一样。代理产生的会话错误标记由本地网关定义，上游同名标记须过滤，不能只按 HTTP 状态码判断。

**交互**：登录页仅提供密码输入、显示/隐藏密码、登录和必要错误反馈；提交中防重复，失败不清空用户正在编辑的输入。已有会话先校验再显示工作区，避免内容闪现。失效时锁定页面，保留本地记录和草稿，登录后回到原视图；不自动重新生成。提供可找到的退出入口。

**访问保护**：页面门禁与服务端权限必须同时实现。未认证 `/api-proxy/`、配置与媒体请求被拒绝；代理不向上游发送会话 Cookie。移除公开静态资源中内嵌的私有配置，不能只加前端弹窗。登录限流，写接口校验来源及 CSRF；NAS 正式访问推荐 HTTPS。

**验收**：正常登录、密码错误、清除 Cookie、固定 7 天边界、浏览器重开、服务不可达、主动退出、多标签退出、密码变更、容器重启均符合预期。手动伪造 localStorage 登录状态不能使用代理，过期令牌被服务端拒绝。源码、静态产物、日志无测试密码和实际供应商 Key。测试时用模拟服务端时间，不必等待 7 天。

**边界验收**：有效供应商 Key 加无效应用会话访问 NAS 代理仍被拒绝，且不请求供应商；有效应用会话加无效供应商 Key 得到上游认证错误但不登出应用。直接调用供应商只发送其所需凭据；代理转发保留供应商 Authorization，去掉 NAS Cookie/CSRF。读取 NAS 中的 API Key 必须先登录。退出应用不会撤销供应商 Key，也不能阻止已持有 Key 的人绕过网页直接调用供应商。

**方案依据**：HttpOnly 限制脚本读取 Cookie，Max-Age 控制浏览器保留时间；服务端仍需独立执行到期和撤销。[MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)、[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
